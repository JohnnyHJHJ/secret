# Decorators and Functions That Wrap Functions

:::goal What you will be able to do
- Treat a function as a value that you can pass and return.
- Accept any number of arguments with `*args` and pass them on.
- Write a decorator, and keep the original name with `@wraps`.
- Solve the Print After Return problem.
:::

In Python a function is a value, like a number. You can store it in a variable or pass it to another function.

:::try t-func-value
Run it. The names `f` and `shout` now refer to the same function.

```python starter
def shout(s):
    return s.upper() + '!'

f = shout
print(f('hi'))
print(f.__name__)
```
:::

::::predict p-func-value
What does this print?

```python
def twice(f, x):
    return f(f(x))

print(twice(lambda n: n + 3, 10))
```
```text answer
16
```
:::hint
`f` is the lambda. It is called two times.
:::
:::hint
First call: 10 becomes 13. Second call: 13 becomes ...
:::
:::explain
`f(f(10))` is `f(13)`, which is 16. The function was passed in just like any other argument.
:::
::::

A decorator must wrap functions with different numbers of arguments. `*args` collects all positional arguments into a tuple. `f(*args)` spreads that tuple back out.

:::try t-star-args
Run it. Then call `show` with three arguments.

```python starter
def show(*args):
    print(args)

show(1, 'a')
show()
show((3,))
```
:::

::::predict p-args
What does this print?

```python
def count(*args):
    return len(args)

print(count(1, 2, 3), count(), count((1, 2, 3)))
```
```text answer
3 0 1
```
:::hint
`args` is a tuple of everything that was passed in.
:::
:::hint
`count((1, 2, 3))` receives **one** argument, which happens to be a tuple.
:::
:::explain
Three arguments give a 3-tuple. No arguments give the empty tuple. A single tuple argument is still just one argument, so the length is 1.
:::
::::

A **decorator** is a function that takes a function and returns a new **wrapper** function. The wrapper runs extra code and calls the original in the middle.

::::fill f-wrapper
```python
def loud(f):
    def wrapper([[*args]]):
        print('calling', f.__name__)
        return f([[*args]])
    return [[wrapper]]
```
:::hint
The wrapper must accept any number of positional arguments.
:::
:::hint
The decorator returns the new function itself, without calling it. What is its name?
:::
:::explain
`*args` in the definition collects, and `*args` in the call spreads. The decorator returns `wrapper` without parentheses: the function, not its result.
:::
::::

Writing `@loud` above a `def` means `add = loud(add)`.

::::predict p-deco
What does this print?

```python
def loud(f):
    def wrapper(*args):
        print('calling', f.__name__)
        return f(*args)
    return wrapper

@loud
def add(a, b):
    return a + b

print(add(2, 3))
```
```text answer
calling add
5
```
:::hint
`add(2, 3)` runs `wrapper(2, 3)`, which prints first.
:::
:::hint
The `print` outside shows what `wrapper` returned.
:::
:::explain
The wrapper prints `calling add`, then returns `f(2, 3)`, which is 5. The outer `print` shows that 5.
:::
::::

:::warning The forgotten return
If `wrapper` calls `f(*args)` but does not `return` it, every call gives back `None`. The decorated function seems to work but its result is lost.
:::

::::quiz q-return
A wrapper contains `f(*args)` on its own line, with no `return`. What does `add(2, 3)` give?

- [ ] `5`
- [x] `None`
- [ ] A `TypeError`
:::hint
What does a function return when it ends without a `return` statement?
:::
:::hint
The wrapper computed 5, but did it hand the value back?
:::
:::explain
The wrapper computes 5 and throws it away, then ends. Functions without `return` give back `None`.

When a decorated function calls itself, it calls the **wrapper**, because the name now refers to the wrapper. That changes the order of the output.

::::predict p-order
What does this print?

```python
def log_call(f):
    def wrapper(n):
        result = f(n)
        print(n, '->', result)
        return result
    return wrapper

@log_call
def fact(n):
    return 1 if n <= 1 else n * fact(n - 1)

fact(3)
```
```text answer
1 -> 1
2 -> 2
3 -> 6
```
:::hint
The print happens after `f(n)` finishes, and `f(3)` needs `fact(2)` first.
:::
:::hint
The innermost call, `fact(1)`, finishes first.
:::
:::explain
`fact(3)` waits for `fact(2)`, which waits for `fact(1)`. Calls finish from the inside out, so the printing starts with the smallest argument. The Print After Return problem shows exactly this order.
:::
::::

A decorated function has the **name of the wrapper**, which hides the original name. `@wraps(f)` from `functools` copies the name (and docstring) onto the wrapper.

::::predict p-wraps
What does this print?

```python
from functools import wraps

def plain(f):
    def wrapper(*args):
        return f(*args)
    return wrapper

def nice(f):
    @wraps(f)
    def wrapper(*args):
        return f(*args)
    return wrapper

@plain
def a():
    return 1

@nice
def b():
    return 2

print(a.__name__, b.__name__)
```
```text answer
wrapper b
```
:::hint
Without `@wraps`, the decorated function is the wrapper itself.
:::
:::hint
With `@wraps(f)`, the wrapper pretends to be `f`.
:::
:::explain
`a` is really `wrapper`, so its name is `wrapper`. `b` carries the name of the function it wraps. This matters when you print `f.__name__` inside a decorator that is itself decorated.
:::
::::

Time to build the real decorator. The problem wants `NAME(ARGS) = RETVAL`, where `ARGS` is each argument's `repr` joined with `", "`. A tempting shortcut is `str(args)`. Try it:

::::exercise ex-single-arg kind=debug
`print_return` prints the call and the result, but the output is wrong when the function has **one** argument (or when the argument is a tuple). Fix how the arguments are shown.

```python starter
def print_return(f):
    def wrapper(*args):
        result = f(*args)
        print(f.__name__ + str(args) + ' = ' + repr(result))
        return result
    return wrapper
```
```python tests
@print_return
def add(a, b):
    return a + b

@print_return
def greet(name):
    return 'hi ' + name

@print_return
def first(t):
    return t[0]

@print_return
def zero():
    return 0

check_output(lambda: add(1, 2), "add(1, 2) = 3", "two arguments")
check_output(lambda: greet('Ana'), "greet('Ana') = 'hi Ana'", "one argument has no trailing comma")
check_output(lambda: first((3,)), "first((3,)) = 3", "one tuple argument")
check_output(lambda: zero(), "zero() = 0", "no arguments")
check(lambda: add(1, 2), 3, "still returns the value")
```
```python solution
def print_return(f):
    def wrapper(*args):
        result = f(*args)
        shown = ', '.join(repr(a) for a in args)
        print(f"{f.__name__}({shown}) = {result!r}")
        return result
    return wrapper
```
:::hint
`str(('Ana',))` is `"('Ana',)"`: a trailing comma and the wrong brackets for one item.
:::
:::hint
Show each argument on its own with `repr(a)`, then join them with `', '`.
:::
:::hint
Put the joined text between the parentheses: `f.__name__ + '(' + shown + ')'`.
:::
:::explain
`str(args)` shows the tuple, and a one-item tuple has a trailing comma. `', '.join(repr(a) for a in args)` shows each argument alone, separated exactly as the problem wants. `repr` keeps the quotes on strings.
:::
::::

::::quiz q-repr
What is the difference between `print('Ana')` and `print(repr('Ana'))`?

- [ ] There is no difference
- [x] The first shows `Ana`, the second shows `'Ana'` with quotes
- [ ] The first shows `'Ana'`, the second shows `Ana`
:::hint
`repr` gives the text you would type to write the value in code.
:::
:::hint
How would you write the string Ana in a Python program?
:::
:::explain
`print` of a string shows the characters only. `repr` adds the quotes (and escapes like `\n`). The problem says the stringified value is its `repr`, so strings must appear with quotes.
:::

::::exercise ex-print-return kind=write
Write the decorator `print_return(f)`. The decorated function must still return what `f` returns. After computing the result it prints one line `NAME(ARGS) = RETVAL`: `NAME` is the function name, `ARGS` are the `repr` of each argument joined with `", "`, and `RETVAL` is the `repr` of the result. Use `@wraps(f)`. No keyword arguments are used.

```python starter
from functools import wraps

def print_return(f):
    @wraps(f)
    def wrapper(*args):
        return f(*args)
    return wrapper
```
```python tests
@print_return
def add(a, b):
    return a + b

@print_return
def greet(name):
    return 'hi ' + name

@print_return
def zero():
    return 0

@print_return
def fib(n):
    return n if n <= 1 else fib(n - 1) + fib(n - 2)

@print_return
def is_subseq(big, sml):
    if not sml:
        return True
    elif not big:
        return False
    elif big[0] == sml[0]:
        return is_subseq(big[1:], sml[1:])
    else:
        return is_subseq(big[1:], sml)

FIB5 = """fib(1) = 1
fib(0) = 0
fib(2) = 1
fib(1) = 1
fib(3) = 2
fib(1) = 1
fib(0) = 0
fib(2) = 1
fib(4) = 3
fib(1) = 1
fib(0) = 0
fib(2) = 1
fib(1) = 1
fib(3) = 2
fib(5) = 5"""

SUB = """is_subseq('', '') = True
is_subseq('a', 'a') = True
is_subseq('na', 'na') = True
is_subseq('ana', 'na') = True
is_subseq('nana', 'nna') = True
is_subseq('anana', 'anna') = True
is_subseq('banana', 'anna') = True"""

check(lambda: add(1, 2), 3, "still returns the value")
check_output(lambda: add(1, 2), "add(1, 2) = 3", "prints name, arguments and result")
check_output(lambda: greet('Ana'), "greet('Ana') = 'hi Ana'", "uses repr for strings")
check_output(lambda: zero(), "zero() = 0", "no arguments")
check_output(lambda: fib(5), FIB5, "recursive calls print the innermost first")
check_output(lambda: is_subseq('banana', 'anna'), SUB, "string arguments")
check(lambda: fib.__name__, 'fib', "keeps the original name")
```
```python solution
from functools import wraps

def print_return(f):
    @wraps(f)
    def wrapper(*args):
        result = f(*args)
        shown = ', '.join(repr(a) for a in args)
        print(f"{f.__name__}({shown}) = {result!r}")
        return result
    return wrapper
```
:::hint
Call `f(*args)` first and keep the result in a variable. That is why the inner calls print before the outer one.
:::
:::hint
Build the argument text with `', '.join(...)` over `repr(a)` for each `a` in `args`.
:::
:::hint
Print the line, then `return result`.
:::
:::explain
The printing happens **after** the call returns, so a recursive function prints its deepest calls first. Keeping `result` in a variable lets you both print it and return it. The `!r` in the f-string means `repr`.
:::
::::

A decorator can also **remember things between calls**. Functions are objects, so you can store an attribute on the wrapper.

::::exercise ex-count-calls kind=challenge
Write a decorator `count_calls(f)` so that the decorated function has an attribute `calls` that counts how many times it has been called. It starts at 0 and the function still returns its normal result.

```python starter
def count_calls(f):
    def wrapper(*args):
        return f(*args)
    wrapper.calls = 0
    return wrapper
```
```python tests
@count_calls
def sq(x):
    return x * x

check(lambda: sq.calls, 0, "starts at 0")
check(lambda: sq(3), 9, "returns the value")
sq(4)
check(lambda: sq.calls, 2, "counted two calls")
check(lambda: sq(5), 25, "still works")
check(lambda: sq.calls, 3, "counted three calls")

@count_calls
def fib(n):
    return n if n <= 1 else fib(n - 1) + fib(n - 2)

fib(10)
check(lambda: fib.calls, 177, "recursive calls are counted too")
```
```python solution
def count_calls(f):
    def wrapper(*args):
        wrapper.calls += 1
        return f(*args)
    wrapper.calls = 0
    return wrapper
```
:::hint
Functions are objects, so `wrapper.calls` is just a variable stored on the function.
:::
:::hint
Increase it inside `wrapper` every time it runs.
:::
:::hint
`wrapper.calls += 1` before returning `f(*args)`.
:::
:::explain
Inside `wrapper`, the name `wrapper` refers to the function itself, so `wrapper.calls += 1` updates the attribute. The counter lives on the function, not in a global variable. Because recursion goes through the wrapper, every recursive call is counted: `fib(10)` makes 177 calls.
:::
::::

:::recap
- Functions are values: pass them in, return them, store them.
- `*args` collects arguments; `f(*args)` passes them on.
- `@d` above `def f` means `f = d(f)`. The decorator returns a `wrapper`.
- Always `return` the result of `f(*args)` from the wrapper.
- Show arguments with `', '.join(repr(a) for a in args)`, never with `str(args)`.
- A recursive decorated function calls its own wrapper, so output appears innermost first.
- `@wraps(f)` keeps the original function's name.
:::
