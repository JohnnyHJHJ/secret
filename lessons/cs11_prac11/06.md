# Sorting, Grouping, Dataclasses and Enums

:::goal What you will be able to do
- Sort with `key=` and with a tuple key, and know how ties and strings are ordered.
- Describe a record with a frozen `dataclass` and a fixed set of choices with an `Enum`.
- Group records into a dict that has a key for every choice, even empty ones.
- Choose between a slow and a fast way to do it, and say why.
:::

`sorted(items)` returns a new sorted list. `key=` is a function that turns each item into the value to sort by.

:::try t-sorted
Run it. Compare the three lines.

```python starter
words = ['pear', 'fig', 'apple', 'kiwi']
print(sorted(words))
print(sorted(words, key=len))
print(sorted(words, key=lambda w: (len(w), w)))
```
:::

A **tuple key** `(a, b)` sorts by `a` first. Only when `a` ties does it look at `b`.

::::predict p-key
What does this print?

```python
words = ['pear', 'fig', 'apple', 'kiwi']
print(sorted(words, key=lambda w: (len(w), w)))
```
```text answer
['fig', 'kiwi', 'pear', 'apple']
```
:::hint
First sort by length: 3, 4, 4, 5.
:::
:::hint
`'kiwi'` and `'pear'` both have length 4. The second part of the key breaks the tie alphabetically.
:::
:::explain
Lengths: fig 3, pear 4, kiwi 4, apple 5. The tie between `kiwi` and `pear` goes to the alphabetical order, so `kiwi` is first.
:::
::::

When two items have equal keys, Python keeps them in their **original order**. We say the sort is **stable**.

::::predict p-stable
What does this print?

```python
pairs = [('b', 1), ('a', 2), ('c', 1), ('d', 2)]
print(sorted(pairs, key=lambda p: p[1]))
```
```text answer
[('b', 1), ('c', 1), ('a', 2), ('d', 2)]
```
:::hint
Sort only by the number. Which items have number 1?
:::
:::hint
`('b', 1)` came before `('c', 1)` in the input, and equal keys keep their order.
:::
:::explain
Both 1s come first, in their original order `b` then `c`. Then both 2s, in their original order `a` then `d`. Stability is why "sort by the second key first, then the first key" also works.
:::
::::

Strings are compared character by character using their code numbers. That puts digits before capital letters, and capital letters before small letters.

::::predict p-string-order
What does this print?

```python
print(sorted(['b', 'B', 'a', 'A', '1']))
```
```text answer
['1', 'A', 'B', 'a', 'b']
```
:::hint
Digits have smaller codes than capital letters.
:::
:::hint
Capital letters have smaller codes than small letters.
:::
:::explain
`'1'` is 49, `'A'` is 65, `'B'` is 66, `'a'` is 97, `'b'` is 98. That is why the movie `'M3GAN'` sorts before `'Morbius'`: at the second character `'3'` is smaller than `'o'`.
:::
::::

A **dataclass** is a short way to write a class that only holds named fields. With `frozen=True` the fields cannot be changed afterwards, and two records with equal fields compare equal.

::::fill f-dataclass
```python
from dataclasses import dataclass

@dataclass([[frozen=True]])
class Movie:
    name: str
    year: int

m = Movie('Up', 2009)
print(m.[[name]], m.year)
```
:::hint
The option that forbids changing fields is called `frozen`.
:::
:::hint
Fields are read with a dot and the field's name.
:::
:::explain
`@dataclass` writes `__init__` and `==` for you from the annotated fields. You read a field with `m.name`.
:::
::::

::::predict p-frozen
What does this print?

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class P:
    x: int

p = P(1)
try:
    p.x = 5
except Exception:
    print('blocked')
print(p.x, p == P(1))
```
```text answer
blocked
1 True
```
:::hint
A frozen dataclass raises an error when you assign to a field.
:::
:::hint
Two dataclass objects with equal fields are equal.
:::
:::explain
The assignment is blocked, so `p.x` is still 1. `P(1) == P(1)` is `True` because dataclasses compare their fields.
:::
::::

An **Enum** is a fixed set of named choices. Looping over the class visits each member once, in the order they were written.

::::predict p-enum
What does this print?

```python
from enum import Enum, auto

class Color(Enum):
    RED = auto()
    BLUE = auto()

for c in Color:
    print(c.name, c.value)
```
```text answer
RED 1
BLUE 2
```
:::hint
Looping over an Enum class visits its members in definition order.
:::
:::hint
`auto()` numbers the members 1, 2, 3, and so on.
:::
:::explain
`c.name` is the name written in the class body and `c.value` is the number `auto()` gave.
:::
::::

Grouping means collecting items into one list per category. The Movie problem wants **every** genre as a key in the result, even a genre with no movies, and the keys in the order of the enum.

::::quiz q-keys
You must return a dict with a key for every member of `Genre`, in enum order, each starting with an empty list. Which line builds it?

- [ ] `result = {}`
- [x] `result = {genre: [] for genre in Genre}`
- [ ] `result = dict(Genre)`
:::hint
You need one key per genre, even before you have seen any movie.
:::
:::hint
A dict comprehension can loop over the enum class.
:::
:::explain
`{genre: [] for genre in Genre}` creates all keys at once, in enum order, each with its own new empty list. Starting from `{}` would leave unused genres missing from the answer.
:::
::::

:::warning The classic grouping bug
Writing `result[key] = [item]` replaces the list every time, so only the last item of each group survives. Use `result[key].append(item)`.
:::

::::exercise ex-group-bug kind=debug
`classify_movies` should put every movie into the list of its genre, sorted by year and then by name. Some movies are missing from the answer. Fix it.

```python starter
from dataclasses import dataclass
from enum import Enum, auto

class Genre(Enum):
    HORROR = auto()
    SCIFI = auto()
    COMEDY = auto()
    ACTION = auto()
    THRILLER = auto()
    DRAMA = auto()
    ROMANCE = auto()
    FANTASY = auto()

@dataclass(frozen=True)
class Movie:
    name: str
    year: int
    genre: Genre

def classify_movies(movies):
    result = {genre: [] for genre in Genre}
    for movie in sorted(movies, key=lambda m: (m.year, m.name)):
        result[movie.genre] = [movie]
    return result
```
```python tests
a = Movie('A', 2001, Genre.HORROR)
b = Movie('B', 1999, Genre.HORROR)
c = Movie('C', 2005, Genre.DRAMA)
out = classify_movies([a, b, c])
check(lambda: out[Genre.HORROR], [b, a], "both horror movies, oldest first")
check(lambda: out[Genre.DRAMA], [c], "one drama")
check(lambda: out[Genre.SCIFI], [], "empty genres stay")
check(lambda: classify_movies([a, b, c, Movie('D', 2001, Genre.HORROR)])[Genre.HORROR], [b, a, Movie('D', 2001, Genre.HORROR)], "same year sorted by name")
```
```python solution
from dataclasses import dataclass
from enum import Enum, auto

class Genre(Enum):
    HORROR = auto()
    SCIFI = auto()
    COMEDY = auto()
    ACTION = auto()
    THRILLER = auto()
    DRAMA = auto()
    ROMANCE = auto()
    FANTASY = auto()

@dataclass(frozen=True)
class Movie:
    name: str
    year: int
    genre: Genre

def classify_movies(movies):
    result = {genre: [] for genre in Genre}
    for movie in sorted(movies, key=lambda m: (m.year, m.name)):
        result[movie.genre].append(movie)
    return result
```
:::hint
Each assignment throws away the list that was already stored for that genre.
:::
:::hint
Add to the existing list instead of replacing it.
:::
:::explain
`result[movie.genre].append(movie)` adds to the list that is already there. Because the movies are sorted first, every genre's list also ends up sorted.
:::
::::

Notice the idea hidden in that solution: **sort once, then split**. When you go through the movies in sorted order and append to the right list, every list is automatically in sorted order too.

```python solution
from dataclasses import dataclass
from enum import Enum, auto

class Genre(Enum):
    HORROR = auto()
    SCIFI = auto()
    COMEDY = auto()
    ACTION = auto()
    THRILLER = auto()
    DRAMA = auto()
    ROMANCE = auto()
    FANTASY = auto()

@dataclass(frozen=True)
class Movie:
    name: str
    year: int
    genre: Genre

def classify_movies(movies):
    result = {genre: [] for genre in Genre}
    for movie in sorted(movies, key=lambda m: (m.year, m.name)):
        result[movie.genre].append(movie)
    return result
```
:::hint
Start with a dict that has an empty list for every genre.
:::
:::hint
Go through the movies in the right order. A tuple key `(year, name)` gives that order.
:::
:::hint
Append each movie to `result[movie.genre]`.
:::
:::explain
Sort once, then distribute. Every list inherits the sorted order. All keys exist from the start, so empty genres are in the answer without extra code.
:::
::::

The real problem has up to 250,000 movies, so speed matters. Look at the next two ways to keep each genre sorted:

- sort **each time** a movie is added to a genre list;
- sort **once** at the start.

::::quiz q-slow
Why is sorting a genre's list again after every single `append` a bad idea for 250,000 movies?

- [ ] It gives a wrong order
- [x] Sorting a growing list again and again does about n times n steps, which is far too slow, while one sort does about n log n
- [ ] `sorted` cannot be called inside a loop
:::hint
Count the work: how big is the list on the last iteration? And you do it on every iteration.
:::
:::hint
For n = 250,000, n times n is more than 60 billion.
:::
:::explain
The answer is correct but quadratic: the work grows with the square of the input size. A single sort of everything costs about n log n, roughly 4.5 million steps for the same input. Judges with big test cases exist to catch exactly this.
:::
::::

::::exercise ex-fast kind=debug timeout=4
This `classify_movies` is correct but too slow: it sorts a genre's list again after every movie. The tests use 40,000 movies. Make it fast.

```python starter
from dataclasses import dataclass
from enum import Enum, auto

class Genre(Enum):
    HORROR = auto()
    SCIFI = auto()
    COMEDY = auto()
    ACTION = auto()
    THRILLER = auto()
    DRAMA = auto()
    ROMANCE = auto()
    FANTASY = auto()

@dataclass(frozen=True)
class Movie:
    name: str
    year: int
    genre: Genre

def classify_movies(movies):
    result = {genre: [] for genre in Genre}
    for movie in movies:
        result[movie.genre] = sorted(result[movie.genre] + [movie], key=lambda m: (m.year, m.name))
    return result
```
```python tests
genres = list(Genre)
big = [Movie('M%d' % ((i * 7919) % 10007), (i * 31) % 1000 + 1, genres[i % 8]) for i in range(40000)]
expected = {g: sorted([m for m in big if m.genre == g], key=lambda m: (m.year, m.name)) for g in Genre}
check(lambda: classify_movies(big) == expected, True, "40,000 movies, sorted and grouped")
small = [Movie('B', 2, Genre.DRAMA), Movie('A', 2, Genre.DRAMA), Movie('Z', 1, Genre.DRAMA)]
check(lambda: classify_movies(small)[Genre.DRAMA], [Movie('Z', 1, Genre.DRAMA), Movie('A', 2, Genre.DRAMA), Movie('B', 2, Genre.DRAMA)], "small case still right")
```
```python solution
from dataclasses import dataclass
from enum import Enum, auto

class Genre(Enum):
    HORROR = auto()
    SCIFI = auto()
    COMEDY = auto()
    ACTION = auto()
    THRILLER = auto()
    DRAMA = auto()
    ROMANCE = auto()
    FANTASY = auto()

@dataclass(frozen=True)
class Movie:
    name: str
    year: int
    genre: Genre

def classify_movies(movies):
    result = {genre: [] for genre in Genre}
    for movie in sorted(movies, key=lambda m: (m.year, m.name)):
        result[movie.genre].append(movie)
    return result
```
:::hint
The slow part is the `sorted(...)` inside the loop.
:::
:::hint
Sort the whole input once, before the loop, then only append inside the loop.
:::
:::explain
One sort of all the movies plus one pass of appends is about n log n work. Because we append in sorted order, each genre's list is sorted without sorting it again.
:::
::::

:::recap
- `sorted(items, key=f)` sorts by `f(item)`. A tuple key breaks ties in order, and equal keys keep their original order.
- Strings compare by character codes: digits, then capitals, then small letters.
- `@dataclass(frozen=True)` makes an unchangeable record; an `Enum` names a fixed set of choices.
- Start a result dict with a key for every choice, then append.
- Sort once and then split, instead of sorting inside a loop.
:::
