# Queues, Rolling Minimums and Functions That Remember

:::goal What you will be able to do
- Use `collections.deque` as a fast queue.
- Keep the minimum of a moving window without rescanning it.
- Write a function that returns another function that remembers things (a **closure**), using `nonlocal`.

:::

A **queue** is first in, first out: you add at the back and remove from the front. A `deque` (say "deck") does both ends quickly.

:::try t-deque
Run it. Then add another `append` and `popleft` and look at the deque.

```python starter
from collections import deque

q = deque([3, 1, 6])
q.append(2)
print(q.popleft())
print(q)
```
:::

:::hint
After the three adds the deque is `1, 5, 7`.

:::hint
`pop()` takes from the back, `popleft()` from the front.

:::explain
`pop()` returns 7, `popleft()` returns 1, and only 5 is left, so the length is 1.

- [ ] `pop(0)` returns the wrong item
- [x] `pop(0)` shifts every other item, so it gets slow on long lists, while `popleft()` does not
- [ ] A `deque` keeps its items sorted

:::
:::hint

:::
:::explain
Removing the front of a list moves all the remaining items one place. A deque is built so both ends are cheap.

Now the main idea. You need the **minimum of the queue**. Looking at every item each time is slow. Instead, keep a second deque `mins` whose values only go **up** from front to back.

Before adding a new value `x`, throw away every value at the back of `mins` that is bigger than `x`. They can never be the minimum again: `x` is smaller and will stay in the queue longer.

::::predict p-mono
What does this print?

```python
from collections import deque

mins = deque()
for x in [4, 2, 5, 1]:
    while mins and mins[-1] > x:
        mins.pop()
    mins.append(x)
    print(list(mins))
```
```text answer
[4]
[2]
[2, 5]
[1]
```
:::hint
For each `x`, first pop from the back while the last value is bigger than `x`.
:::
:::hint
For `x = 1`, both 5 and 2 are bigger than 1.
:::
:::explain
4 is removed by 2. 5 is kept because 2 < 5. Then 1 removes 5 and 2. The front of `mins` is always the smallest value seen so far that is still useful.
:::

A real window **expires** old items. If we store **indexes** in the deque, we can drop the front index once it falls out of the window.

```python tests
check(lambda: sliding_min([4, 2, 5], 1), [4, 2, 5], "k = 1")
check(lambda: sliding_min([3, 1, 2], 3), [1], "window as long as the list")
check(lambda: sliding_min([2, 2, 2, 2], 2), [2, 2, 2], "equal values")
```

```python solution
from collections import deque

def sliding_min(nums, k):
    d = deque()
    result = []
    for i in range(len(nums)):
        while d and nums[d[-1]] >= nums[i]:
            d.pop()
        d.append(i)
        if d[0] <= i - k:
            d.popleft()
        if i >= k - 1:
            result.append(nums[d[0]])
    return result
```
:::hint
Steps 1 and 2 are the loop you just practised, but compare `nums[d[-1]]` with `nums[i]` because `d` holds indexes.
:::
:::hint
The window ending at `i` covers indexes `i - k + 1` to `i`. So the front index has expired when it is `<= i - k`.
:::
:::hint
The first full window ends at `i = k - 1`. Only from then on append `nums[d[0]]` to `result`.
:::
:::explain
Each index is added once and removed at most once, so the whole thing is fast. Only one front index can expire per step, because exactly one new index was added.
:::

The Queuery problem wants something different: a function `rolling_queue(initial)` that **returns a function**. Each call of that returned function adds one number and answers a minimum. The returned function must **remember** the queue between calls.

A function defined inside another function can use the outer function's variables. That is a **closure**.

:::try t-closure
Run it. Each counter keeps its own `count`. Try making a third counter.

```python starter
def make_counter():
    count = 0
    def step():
        nonlocal count
        count += 1
        return count
    return step

a = make_counter()
print(a(), a(), a())
```
:::

::::quiz q-nonlocal
Inside `step`, you write `count += 1` but you forget the line `nonlocal count`. What happens when `step()` is called?

- [ ] It adds 1 to the outer `count`
- [x] It raises `UnboundLocalError`, because `count` is treated as a new local variable
- [ ] It returns 0
:::hint
Assigning to a name inside a function makes that name local to the function, unless you say otherwise.
:::
:::hint
The local `count` has no value yet when `+= 1` tries to read it.
:::
:::explain
`count += 1` means `count = count + 1`, and an assignment makes `count` local. `nonlocal count` tells Python to use the one from the outer function. You only need it when you **rebind** the name; changing a deque with `append` does not rebind anything.
:::
::::

:::warning The error message
`UnboundLocalError: cannot access local variable 'count' where it is not associated with a value` means you assigned to a name in an inner function without `nonlocal`.
:::

::::exercise ex-runmax kind=write
Write `make_running_max()` that returns a function. Each call of that function takes a number and returns the **largest number given so far**, including the new one. Two running maxima must be independent.

```python starter
def make_running_max():
    def add(x):
        return x
    return add
```
```python tests
m = make_running_max()
check(lambda: m(3), 3, "first number")
check(lambda: m(1), 3, "smaller number")
check(lambda: m(7), 7, "bigger number")
check(lambda: m(-1), 7, "negative number")
n = make_running_max()
check(lambda: n(-5), -5, "a new one starts fresh, even with negatives")
check(lambda: m(2), 7, "the first one is unchanged")
```
```python solution
def make_running_max():
    best = None
    def add(x):
        nonlocal best
        if best is None or x > best:
            best = x
        return best
    return add
```
:::hint
You need a variable in the outer function that survives between calls.
:::
:::hint
Start it as `None`, not 0, so that a first negative number still works.
:::
:::hint
Use `nonlocal best` inside `add`, update `best` when `x` is bigger, then return `best`.
:::
:::explain
Starting at 0 would be wrong for negative numbers. `None` plus the check `best is None` handles the first call. `nonlocal` is needed because `best = x` rebinds the name.
:::

Now combine the two ideas. A first version of `rolling_queue` is below. It uses a monotonic deque of **values**, not indexes: when the front of the queue leaves, we remove it from `mins` only if it is the value at the front of `mins`.

It passes the sample, but there is a bug with **equal** values.

::::exercise ex-dup kind=debug
`rolling_queue` gives wrong answers when the queue contains equal numbers. Find the comparison that throws equal values away too early and fix it. (Check `rolling_queue([2, 2])` followed by `op(5)` and `op(9)`.)

```python starter
from collections import deque

def rolling_queue(initial):
    queue = deque(initial)
    mins = deque()
    for x in initial:
        while mins and mins[-1] >= x:
            mins.pop()
        mins.append(x)
    def op(x):
        queue.append(x)
        while mins and mins[-1] >= x:
            mins.pop()
        mins.append(x)
        smallest = mins[0]
        front = queue.popleft()
        if mins[0] == front:
            mins.popleft()
        return smallest
    return op
```
```python tests
def two_twos():
    op = rolling_queue([2, 2])
    return [op(5), op(9), op(9)]
check(two_twos, [2, 2, 5], "equal values must both stay in mins")
def simple():
    op = rolling_queue([3, 1, 6])
    return [op(2), op(2)]
check(simple, [1, 1], "the simple case still works")
```

```python solution
    mins = deque()
    for x in initial:
        while mins and mins[-1] > x:
            mins.pop()
        mins.append(x)
    def op(x):
        queue.append(x)
        while mins and mins[-1] > x:
            mins.pop()

```
:::hint
Trace `[2, 2]`: after the first 2, what does the second 2 do to `mins` with `>=`?
:::
:::hint
If both 2s are not in `mins`, then removing one 2 from the front also removes the other from `mins`, while a 2 is still in the queue.
:::
:::hint
Remove from the back only values that are **strictly** bigger than `x`. There are two places.
:::
:::explain
With `>=`, the second 2 pops the first 2, so `mins` holds one 2 for two queue items. When the front 2 leaves, `mins` loses its only 2 although another 2 is still in the queue. Keeping equal values (use `>`) keeps one entry per queue item that could still be the minimum.
:::

```python solution
from collections import deque

def rolling_queue(initial):
    queue = deque(initial)
    mins = deque()
    for x in initial:
        while mins and mins[-1] > x:
            mins.pop()
        mins.append(x)
    def op(x):
        queue.append(x)
        while mins and mins[-1] > x:
            mins.pop()
        mins.append(x)
        smallest = mins[0]
        front = queue.popleft()
        if mins[0] == front:
            mins.popleft()
        return smallest
    return op
```
:::hint
Keep two deques inside `rolling_queue`: the real queue and a deque `mins` of values that only go up.
:::
:::hint
`op` is a closure. It uses `queue` and `mins` without rebinding them, so it does not even need `nonlocal`.
:::
:::hint
Order of steps inside `op`: add `x` to the queue, trim and extend `mins`, read `mins[0]`, then `popleft` the queue and, if that value equals `mins[0]`, `popleft` `mins` as well.
:::
:::explain
Every value enters and leaves each deque at most once, so each call costs a tiny constant amount on average. A solution that calls `min(queue)` each time looks at 100,000 items per call and runs out of time. This is the difference between the 150 points for small cases and the full score.
:::
::::

:::recap
- A `deque` gives fast `append`, `pop`, `appendleft` and `popleft`.
- Keep a second deque whose values only go up: trim bigger values from the back, add the new value, and the front is the minimum.
- Equal values must stay: remove from the back only values that are **strictly** bigger.
- A function defined inside another function remembers the outer variables: a closure. Use `nonlocal` when you rebind a name.
- Every call of the outer function creates new, independent state.
:::
