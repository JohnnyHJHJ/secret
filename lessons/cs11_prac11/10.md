# Recursion on Numbers, Strings and Sequences

:::goal What you will be able to do
- Write a recursive function with a base case and a recursive case.
- Trace the order in which recursive calls start and finish.
- Recurse on strings and tuples using slices.
- Write a generator with `yield`, and use it to build merge sort.
:::

A **recursive** function calls itself on a smaller problem. It needs two parts:

- a **base case**: an input so small that the answer is known at once;
- a **recursive case**: solve the smaller problem, then use its answer.

:::try t-countdown
Run it. Then change `3` to `5`.

```python starter
def countdown(n):
    if n == 0:
        print('liftoff')
    else:
        print(n)
        countdown(n - 1)

countdown(3)
```
:::

Notice that code after the recursive call runs **when that call comes back**.

::::predict p-trace
What does this print?

```python
def countdown(n):
    if n == 0:
        print('liftoff')
    else:
        print(n)
        countdown(n - 1)
        print('back', n)

countdown(2)
```
```text answer
2
1
liftoff
back 1
back 2
```
:::hint
The calls go down first: 2, then 1, then 0.
:::
:::hint
Each `print('back', n)` runs only after the deeper call has finished.
:::
:::explain
`countdown(2)` prints 2 and calls `countdown(1)`, which prints 1 and calls `countdown(0)`. That prints `liftoff` and returns. Then `countdown(1)` continues and prints `back 1`, then `countdown(2)` prints `back 2`.
:::

:::explain
Without a base case the function calls itself forever (until Python raises `RecursionError`). The base case is where the chain of calls ends and answers begin to come back.

Sequences shrink nicely with **slices**: `items[1:]` is everything except the first item, `items[:h]` is the first `h` items.

::::predict p-slice
What does this print?

```python
s = 'banana'
print(s[1:], s[:2], s[2:4], s[::-1])
```
```text answer
anana ba na ananab
```
:::hint
`s[1:]` drops the first character.
:::
:::hint
`s[2:4]` starts at position 2 and stops before 4. `s[::-1]` is the reversed string.
:::
:::explain
`'banana'[1:]` is `'anana'`, `[:2]` is `'ba'`, `[2:4]` is `'na'`, and `[::-1]` reverses the string to `'ananab'`.
:::

::::exercise ex-total kind=write
Write `total(items)` that returns the sum of a tuple of numbers **recursively**: the sum of an empty tuple is 0, otherwise it is the first item plus the sum of the rest.

```python starter
def total(items):
    return 0
```
```python tests
check(lambda: total((1, 2, 3)), 6, "three numbers")
check(lambda: total(()), 0, "empty tuple")
check(lambda: total((5,)), 5, "one number")
check(lambda: total((-1, 1)), 0, "negative number")
check(lambda: total(tuple(range(100))), 4950, "a longer tuple")
check(calls('total'), True, "calls itself")
```
```python solution
def total(items):
    if not items:
        return 0
    return items[0] + total(items[1:])
```
:::hint
The base case is the empty tuple. `not items` is `True` for it.
:::
:::hint
The recursive case: `items[0]` plus the total of `items[1:]`.
:::
:::explain
Every call works on a tuple one item shorter, so the chain ends at the empty tuple. Then the additions happen on the way back, from the last item to the first.
:::
::::

:::warning RecursionError
`RecursionError: maximum recursion depth exceeded` means the function keeps calling itself without reaching a base case, or the base case is never hit for some inputs.
:::

::::exercise ex-no-base kind=debug
`length(s)` should return the number of characters of a string, recursively. It crashes with `RecursionError`. Fix it.

```python starter
def length(s):
    return 1 + length(s[1:])
```
```python tests
check(lambda: length('abc'), 3, "three characters")
check(lambda: length(''), 0, "empty string")
check(lambda: length('a'), 1, "one character")
check(lambda: length('banana'), 6, "banana")
```
```python solution
def length(s):
    if s == '':
        return 0
    return 1 + length(s[1:])
```
:::hint
What should happen when the string is empty? Right now it still calls itself.
:::
:::hint
Add a base case at the top that returns 0 for the empty string.
:::
:::explain
`s[1:]` of an empty string is again the empty string, so without a base case the calls never stop. The base case answers the smallest input directly.

Now a classic: is one string a **subsequence** of another? `'anna'` is a subsequence of `'banana'`: you can find its letters in order (not necessarily next to each other) by skipping some letters.

::::exercise ex-subseq kind=write
Write `is_subseq(big, sml)`. Cases, in this order:

1. `sml` is empty: `True`.
2. `big` is empty: `False`.
3. The first characters are equal: look at the rest of both.
4. Otherwise: skip the first character of `big` and keep `sml`.

```python starter
def is_subseq(big, sml):
    return False
```
```python tests
check(lambda: is_subseq('banana', 'anna'), True, "anna is in banana")
check(lambda: is_subseq('banana', 'anne'), False, "anne is not")
check(lambda: is_subseq('abc', ''), True, "empty is always a subsequence")
check(lambda: is_subseq('', 'a'), False, "nothing to pick from")
check(lambda: is_subseq('abc', 'cba'), False, "order matters")
check(lambda: is_subseq('abc', 'ac'), True, "skipping a letter")
check(lambda: is_subseq('', ''), True, "both empty")
check(calls('is_subseq'), True, "calls itself")
```
```python solution
def is_subseq(big, sml):
    if not sml:
        return True
    elif not big:
        return False
    elif big[0] == sml[0]:
        return is_subseq(big[1:], sml[1:])
    else:
        return is_subseq(big[1:], sml)
```
:::hint
Write the four cases as `if / elif / elif / else`, in the order given.
:::
:::hint
For case 3, drop one character from **both** strings. For case 4, drop one from `big` only.
:::
:::hint
Check `sml` being empty **before** `big` being empty, so `('', '')` gives `True`.
:::
:::explain
The order of the base cases matters: an empty `sml` is already matched, even when `big` is also empty. Each call shortens `big`, so the recursion always ends.
:::

Recursion can also **build** a result on the way back. This function makes the `n` letters that start at letter number `s`.

::::fill f-alph
```python
def alph(n, s):
    return '' if n == [[0]] else chr(ord('a') + s) + alph(n - [[1]], s + 1)

print(alph(5, 0))
```
:::hint
The base case is "no letters left". What is `n` then?
:::
:::hint
Each call asks for one letter fewer.
:::
:::explain
`ord('a')` is 97, so `chr(ord('a') + s)` is the letter number `s`. Each call makes one letter and asks the recursion for the rest: `alph(5, 0)` is `'a' + alph(4, 1)`, and so on down to `''`.
:::

::::exercise ex-reverse kind=write
Write `reverse(s)` that returns the string reversed, **recursively** (do not use the `[::-1]` slice). The reverse of the empty string is the empty string. Otherwise it is the reverse of the rest followed by the first character.

```python starter
def reverse(s):
    return s
```
```python tests
check(lambda: reverse('abc'), 'cba', "abc")
check(lambda: reverse(''), '', "empty")
check(lambda: reverse('a'), 'a', "one letter")
check(lambda: reverse('banana'), 'ananab', "banana")

check('[::-1]' not in SOURCE, True, "no slice trick")
```
```python solution
def reverse(s):
    if s == '':
        return ''
    return reverse(s[1:]) + s[0]
```
:::hint
What is the reverse of the empty string?
:::
:::hint
For `'abc'`: reverse `'bc'` gives `'cb'`. What must you add to get `'cba'`?
:::
:::explain
The first character moves to the end: `reverse(s[1:]) + s[0]`. The result is assembled on the way back.

Merge sort uses recursion to split a sequence in half, sort each half, and then **merge** the sorted halves. The merge step is neatly written as a **generator**: a function with `yield` that hands out values one at a time.

:::try t-yield
Run it. A generator does not run all at once: each `yield` pauses it.

```python starter
def count_up(n):
    for i in range(n):
        yield i

print(list(count_up(3)))
for x in count_up(2):
    print('got', x)
```
:::

::::predict p-yield
What does this print?

```python
def gen():
    print('start')
    yield 1
    print('middle')
    yield 2
    print('end')

for x in gen():
    print('got', x)
```
```text answer
start
got 1
middle
got 2
end
```
:::hint
The generator runs until its first `yield`, then pauses.
:::
:::hint
The loop body runs while the generator is paused. Then the generator continues.
:::
:::explain
`start` prints, then `yield 1` hands over 1 and pauses, so the loop prints `got 1`. Then the generator resumes, prints `middle`, yields 2, and so on. After the last `yield` it prints `end` and finishes.
:::

::::exercise ex-merge kind=write
Write the generator `merge(a, b)` that takes two **sorted** sequences and yields all their items in sorted order. Use two positions `i` and `j`, and `yield` the smaller current item each time.

```python starter
def merge(a, b):
    i = 0
    j = 0
    # yield the items here
    return
    yield
```
```python tests
check(lambda: list(merge((1, 3, 5), (2, 4))), [1, 2, 3, 4, 5], "interleaved")
check(lambda: list(merge((), (1,))), [1], "left empty")
check(lambda: list(merge((1,), ())), [1], "right empty")
check(lambda: list(merge((), ())), [], "both empty")
check(lambda: list(merge((1, 2), (1, 3))), [1, 1, 2, 3], "equal items")
check(lambda: list(merge((1, 2, 3), (7, 8))), [1, 2, 3, 7, 8], "one list is entirely smaller")
check(uses('Yield'), True, "uses yield")
```
```python solution
def merge(a, b):
    i = 0
    j = 0
    while i < len(a) or j < len(b):
        if j >= len(b) or (i < len(a) and a[i] <= b[j]):
            yield a[i]
            i += 1
        else:
            yield b[j]
            j += 1
```
:::hint
Loop while at least one sequence still has items: `i < len(a) or j < len(b)`.
:::
:::hint
Take from `a` when `b` is used up, or when `a` has an item that is not bigger than `b`'s current item.
:::
:::hint
Otherwise take from `b`. After each `yield`, move that sequence's position forward.
:::
:::explain
Two sorted sequences only need their **front** items compared. The condition `j >= len(b) or (...)` must come first, so that we never read `b[j]` past its end. Using `<=` takes from `a` on ties.
:::

::::exercise ex-msort kind=complete
Finish `merge_sort(seq)`: it returns the items of `seq` as a sorted **tuple**. A sequence of length 0 or 1 is already sorted. Otherwise split it at `len(seq) // 2`, sort both halves recursively, and merge them. `merge` is given.

```python starter
def merge(a, b):
    i = 0
    j = 0
    while i < len(a) or j < len(b):
        if j >= len(b) or (i < len(a) and a[i] <= b[j]):
            yield a[i]
            i += 1
        else:
            yield b[j]
            j += 1

def merge_sort(seq):
    return tuple(seq)
```
```python tests
check(lambda: merge_sort((3, 1, 4, 1, 5, 9, 2, 6)), (1, 1, 2, 3, 4, 5, 6, 9), "the sample")
check(lambda: merge_sort(()), (), "empty")
check(lambda: merge_sort((7,)), (7,), "one item")
check(lambda: merge_sort((2, 1)), (1, 2), "two items")
check(lambda: merge_sort(tuple(range(200, 0, -1))), tuple(range(1, 201)), "a reversed run of 200")
check(calls('merge_sort'), True, "calls itself")
```
```python solution
def merge(a, b):
    i = 0
    j = 0
    while i < len(a) or j < len(b):
        if j >= len(b) or (i < len(a) and a[i] <= b[j]):
            yield a[i]
            i += 1
        else:
            yield b[j]
            j += 1

def merge_sort(seq):
    if len(seq) <= 1:
        return tuple(seq)
    h = len(seq) // 2
    return tuple(merge(merge_sort(seq[:h]), merge_sort(seq[h:])))
```
:::hint
The base case: a sequence of length 0 or 1 is already sorted.
:::
:::hint
Split with `h = len(seq) // 2`, so `seq[:h]` is the left half and `seq[h:]` is the right half.
:::
:::hint
`tuple(merge(left_sorted, right_sorted))` turns the generator into a tuple.
:::
:::explain
Halving makes the problem smaller each time, and merging two sorted halves is a single pass. The recursion depth is only about log of the length, so it is both safe and fast.
:::

Let us see the order of calls once more, with a decorator from the previous lesson.

::::predict p-tree
What does this print?

```python
def show(f):
    def wrapper(seq):
        result = f(seq)
        print(seq, '->', result)
        return result
    return wrapper

@show
def msort(seq):
    if len(seq) <= 1:
        return seq
    h = len(seq) // 2
    left = msort(seq[:h])
    right = msort(seq[h:])
    return sorted(left + right)

msort([3, 1, 2])
```
```text answer
[3] -> [3]
[1] -> [1]
[2] -> [2]
[1, 2] -> [1, 2]
[3, 1, 2] -> [1, 2, 3]
```
:::hint
The print comes after the call returns, so the smallest calls print first.
:::
:::hint
For `[3, 1, 2]` the left half is `[3]` and the right half is `[1, 2]`. The left is finished before the right starts.
:::
:::explain
`msort([3, 1, 2])` first sorts `[3]` (prints), then `[1, 2]`, which first sorts `[1]` and `[2]` (both print) and then prints itself. Finally the whole list prints. Output order is: left side fully, right side fully, then the parent.
:::
::::

:::recap
- A recursive function has a base case and a recursive case that works on a smaller input.
- Code after the recursive call runs on the way back; results are assembled from the smallest case outwards.
- Slices shrink sequences: `s[1:]`, `s[:h]`, `s[h:]`.
- Put base cases in the right order: `sml` empty before `big` empty.
- `yield` makes a generator that hands out values one at a time and pauses in between.
- Merge sort: split in half, sort the halves recursively, merge them.
:::
